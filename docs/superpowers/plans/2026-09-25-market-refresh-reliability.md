# 시장 데이터 갱신 개선 구현 계획

목표: 최신 종가 확보를 빠르고 제한된 시간 안에 시도하고, 저장과 화면 반영의 실패를 구분한다.
범위: 전략 설정과 포지션을 변경하지 않는다. 운영 배포는 별도 승인 후 진행한다.

- [x] 1. 조회/저장 소요시간과 요청/반환 날짜 로그 추가. 기존 API 테스트 통과.
- [x] 2. FDR 작업을 별도 프로세스에서 15초로 제한. 최초 실패도 하루 보완 경로로 연결. 시간 초과/복구 테스트 통과.
- [x] 3. 각 화면 응답 독립 반영, 최신 요청 보호 유지. 보조 요청 실패 및 오래된 응답 테스트 통과.
- [x] 4. 400일 범위에 200행 이상 확보 시 최근 저장일에서 7일 겹쳐 재조회. 최초/불충분 이력은 전체 조회. full_history=true API 옵션으로 과거 재검증 가능. 공통 시세 선택, SQLite 일괄 upsert와 최신 1행 조회 적용.
- [x] 5. 투자종목 실패는 기존 503 유지. 투자종목 성공 후 RSI/추세 종목 실패는 warnings 및 실제 저장 날짜를 반환하고 일부 갱신으로 표시. 백엔드 346개, 프론트 35개 통과 및 빌드 성공.

검증: 주 공급자 오류/누락/시간 초과, 보조 성공/실패, 휴장, 중복 날짜, 일부 종목 실패, UI 보조 요청 실패, 과거 재조회.
주의: 수정주가라는 기존 필드는 실제 공급자 출처의 완전한 대체가 아니다. 종가 보완과 과거 수정가격 재검증을 구분하며 출처는 로그로 추적한다.

검증 기록: 로컬 실제 공급자 조회 약 1.6초, 마지막 시세 2026-09-24. 운영 서버 성능과 브라우저 시각 검증은 아직 수행하지 않음. 15초는 주 공급자 요청 한 번의 제한이며 전체 갱신 시간 상한이 아님. 보조 공급자와 복수 종목 재시도 시간이 추가될 수 있음. 운영 DB와 전략 설정은 변경하지 않았으며 배포는 별도 승인 필요.
