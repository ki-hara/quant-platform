# 시장 데이터 갱신 개선 구현 계획

목표: 최신 종가 확보를 빠르고 제한된 시간 안에 시도하고, 저장과 화면 반영의 실패를 구분한다.
범위: 전략 설정과 포지션을 변경하지 않는다. 운영 배포는 별도 승인 후 진행한다.

- [ ] 1. market_refresh_service에 종목·요청 날짜·반환 날짜·조회/저장 소요시간과 실패 로그를 추가한다. 기존 API 테스트 후 커밋한다.
- [ ] 2. FinanceDataReader 조회를 시간 제한이 있는 별도 프로세스에 격리한다. 초과 시 종료/회수하여 무한 대기 작업을 남기지 않는다. 최초 조회 예외도 단일 거래일 보완 경로로 연결하고 시간 초과/누락 테스트 후 커밋한다.
- [ ] 3. DashboardPage에서 모드·주문표·대시보드·차트·내역을 독립 반영한다. 최신 요청 보호를 유지하고 부분 실패를 표시한다. 타입 검사·프론트 테스트 후 커밋한다.
- [ ] 4. 기존 데이터가 충분하면 최근 구간만 갱신한다. 최초 조회와 명시적 과거 재검증은 400일 유지한다. 중복 선택 규칙을 저장소에 모으고 일괄 upsert, 최신 1행 쿼리로 변경한다. 저장 오류 rollback과 회귀 테스트 후 커밋한다.
- [ ] 5. 종목별 부분 성공을 응답에 포함하고 RSI 실패 시 새 추천을 계산하지 않는다. 전체 백엔드/프론트 테스트와 빌드로 검증한다.

검증: 주 공급자 오류/누락/시간 초과, 보조 성공/실패, 휴장, 중복 날짜, 일부 종목 실패, UI 보조 요청 실패, 과거 재조회.
주의: 수정주가라는 기존 필드는 실제 공급자 출처의 완전한 대체가 아니다. 종가 보완과 과거 수정가격 재검증을 구분하며 출처는 로그로 추적한다.
